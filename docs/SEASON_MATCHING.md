# 电视剧季集匹配与确认

日期：2026-10-24。本文描述 Mnemo 如何从资源名称和已确认作品身份判断季集，以及哪些情况会阻止下载、哪些情况必须由用户确认。匹配依据仅为名称与元数据，不代表已核对视频内容。

## 结论

- 单集资源只有在完整片名、唯一年份、唯一季号和唯一集号全部一致时才是`matched`。
- 多集区间、整季包、合集、多季范围不会被当成所选单集；已识别为`mismatch`的资源不能下载，也不能靠确认绕过。
- 缺失唯一年份或季集证据的资源是`uncertain`，只有用户显式确认后才能创建任务。
- 片名中一次指定多季或多集会在调用媒体源前被拒绝，要求改为一次一季或一集。
- 电视剧下载在未指定季集时进入详情步骤：下载必须选择季号和集号；订阅必须选择季号，开始集可选。
- 目录绑定只补全可信上下文，不覆盖冲突；`1080.mp4`、`2160.mp4`等分辨率文件名不会被当成第1080集或第2160集。

## 名称识别矩阵

| 名称特征 | 示例 | 识别结果 | 下载行为 |
|---|---|---|---|
| 标准单集 | `S02E03`、`2x03`、`Season 2 Episode 3` | 季2、集3 | 身份与年份一致且只有一个可下载匹配资源时自动下载，否则由用户选择 |
| 中文单集 | `第2季 第3集`、`第二季第三集` | 季2、集3 | 同上 |
| 全角写法 | `Ｓ０１Ｅ０２`、`第２季 第３集` | 先做 NFKC 归一化再识别 | 同上 |
| 多集区间 | `S02E01-E03`、`1x01-03`、`第2-4集` | 多集包 | 所选单集为`mismatch`，不能下载或确认 |
| 多集列表 | `S01E01E02`、`第2、3、4集`、`第2,3,4集`、`第2到4集`、`第2—4集` | 多集包 | 所选单集为`mismatch`，不能下载或确认 |
| 省略第二集前缀 | `S01E02 03`、`E02 03` | 多集包 | 所选单集为`mismatch`，不能下载或确认 |
| 整季或合集 | `S02 Complete`、`全集`、`全10集`、`合集` | 整包 | 所选单集为`mismatch`，不能下载或确认 |
| 仅季号 | `S02`、`第2季` | 有季无集 | 所选单集为`uncertain`，必须明确确认；不会自动下载 |
| 多季范围 | `Season 1-2`、`Seasons 1&2`、`S01-S02`、`第1-2季`、`第一、二季` | 记录两端季号并标记为包 | 不能当作单季或单集；在片名中一次指定多季会被直接拒绝 |
| 错季 | 选季2，资源为`S01E03` | 季号冲突 | `mismatch`，不能下载或确认 |
| 错集 | 选集3，资源为`S02E04` | 集号冲突 | `mismatch`，不能下载或确认 |
| 错年或类型冲突 | 选2023年电视剧，资源为2024年或`movie` | 身份冲突 | `mismatch`，不能下载或确认 |
| 缺少年份 | `The.Last.of.Us.S02E03` | 无唯一年份证据 | `uncertain`，必须明确确认 |
| 缺失唯一季集 | `video.mp4`、无法解析的命名 | 证据不足 | `uncertain`，必须明确确认 |
| 预告、花絮、字幕 | `S01E03.Trailer`、`第3集.花絮` | 附加内容 | `mismatch`，不能下载 |
| 目录数字文件名 | 可信目录下的`03.mp4`、`003.mp4` | 集3 | 由目录补全身份与季号，仍须满足完整匹配条件 |
| 目录分辨率文件名 | `360.mp4`、`480.mp4`、`576.mp4`、`720.mp4`、`1080.mp4`、`1440.mp4`、`2160.mp4`、`4320.mp4` | 分辨率元数据，不是集号 | `uncertain`，必须明确确认，不会自动成为第1080集等 |
| 多季或冲突目录 | 绑定目录含`Season 1-2`、`S02`或另一作品 | 上下文冲突 | `mismatch`，不能下载 |

`S01E02 5.1`、`S01E02 1080p`、`S01E02 2023`、`S01E02 2ch`和`S01E02 x264`仍识别为第2集，但其中的分数、分辨率、年份、声道和编码片段不会被提升为额外集号。`S01E02.5`这类明确分数集不会伪装成完整单集。

## 确认与阻止规则

请求状态机按以下顺序执行：

1. 解析片名中的季集提示。若一次出现多季、多集或包特征，立即返回“请一次指定一季或一集”，不会调用身份查询或资源搜索，也不会写入请求记录。
2. 身份查询后，只有完整片名唯一匹配才自动进入搜索；否则等待用户选择候选或手动填写电影/剧集、完整片名和年份。
3. 资源搜索完成后，每个候选标记为`matched`、`uncertain`或`mismatch`。
4. 下载阶段再次以服务端保存的作品和季集复核资源，不能用旧视图或客户端伪造字段替换。
5. 只有唯一一个可下载候选且其状态为`matched`时才自动创建任务；存在多个候选时由用户选择。
6. `uncertain`必须携带`confirmUncertain: true`才会创建任务；`mismatch`即使携带确认也返回错误。
7. 请求修订号过期返回409，避免在季集已变化后复用旧选择。

电视剧详情步骤的硬性要求：

- `download`：季号和集号都必须提供。
- `subscribe`：季号必须提供；开始集可选，用于从指定集开始追更。
- 电影不能提交季号或集号。

## 目录绑定

绑定到已浏览目录的电视剧可以补全缺失的作品身份和季号，但不会覆盖明确的文件或目录冲突：

- 可信目录含`The Last of Us (2023)`和`Season 1`时，`03.mp4`可识别为第1季第3集。
- 目录和文件分别给出不同季号、集号、年份或身份时，结果为`mismatch`。
- 目录或文件含`全集`、多集区间、多集列表、预告或花絮时，不会自动下载。
- 纯数字文件名只有在不是年份和常见分辨率时才按集号处理；`1080`等保留为分辨率元数据并进入人工确认。
- 目录绑定不能证明文件内容或网盘分享权益，只是名称层面的可信上下文。

## 下载布局与媒体库识别

电视剧只有在季集证据成立后才使用以下布局：

```text
剧名 (年份)/
  tvshow.nfo
  Season 01/
    剧名 (年份) - S01E02.ext
    剧名 (年份) - S01E02.nfo
```

- 单集 NFO 使用 `episodedetails`，写入 `showtitle`、`season`、`episode`、年份、简介和可确认的 TMDB `uniqueid`；没有确认的 TMDB 身份时不伪造 `uniqueid`。
- 剧集根目录的 `tvshow.nfo` 是稳定文件，写入剧名、年份、剧集简介和剧集 TMDB id；已存在时复用，不覆盖用户文件。
- 嵌套路径必须位于下载根目录内，季目录只允许 `Season NN` 形式；符号链接、越界路径和非规范目录会被拒绝。
- Emby 对“平铺的单集文件 + NFO”可能只识别为 Episode 而不建立 SeriesId；标准剧集/季目录加 `tvshow.nfo` 后才能稳定关联 SeriesId/SeriesName。因此目录布局是播放正确性的一部分，不只是整理偏好。

## 复现验收

在项目目录执行：

```sh
npm run verify:season
```

该命令依次运行季集定向测试、全套 Node 测试、TypeScript 检查和 Vite 构建，并把命令、退出状态、测试计数、耗时、构建产物及关键文件 SHA-256 写入`docs/evidence/season-matching-20261024.json`。任一命令失败时验收脚本以非零状态退出。

电视剧下载布局和媒体库识别另有隔离全链路验收，需要 Docker：

```sh
docker build -t mori-media-agent:tv-fullchain-20261024 .
python3 scripts/verify_emby_tv_fullchain.py
```

可用 `MORI_TV_FULLCHAIN_IMAGE` 指定已有镜像。该脚本从 HTTP 裸片名开始，验证详情步骤强制季集、聚合订阅、正确季资源唯一入队、嵌套目录与两份 NFO、Emby Episode/SeriesId/路径，以及完整媒体流 SHA-256 和 ffmpeg 解码。日志与回执写入 `output/verification/fullchain-tv-runs/<runId>/`，验收副本为 `docs/evidence/fullchain-tv-emby-20261024.json`。

手工复核可使用：

```sh
npx tsx --test tests/matching.test.ts tests/directory-matching.test.ts tests/requests.test.ts
npm test
npm run check
npm run build
```

最新记录：43 项定向测试、451 项全套测试通过；TypeScript 和 Vite 构建通过。完整回执以生成的证据文件为准。

## 仍未覆盖

- 只根据名称和已确认元数据匹配，不读取视频内容、不核对文件内季集。
- 不同来源的未知命名变体可能只能进入`uncertain`或`mismatch`，仍需人工判断。
- 合集、多视频拆分和跨来源自动归并未在本轮实现。
- 定向测试使用受控身份与资源；没有真实 TMDB、PanSou、网盘账号、物理NAS或用户媒体库参与。隔离 Emby 是实际服务，但作品身份与搜索源是受控样例，不构成真实账号下载权益或生产播放验收。
- Windows、物理飞牛/绿联及真实平台渠道仍未验收，详见[用户需求与验收边界](ACCEPTANCE.md)。
