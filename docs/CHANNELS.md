# 模型与消息渠道

模型配置由管理员自行填写。填写服务地址与模型名后使用所配置服务的 OpenAI-compatible `POST /chat/completions`；本地免密钥模型可将密钥留空，此时不发送 Authorization。服务需支持 JSON response format。缺少服务地址或模型名时，聊天明确显示“规则模式”；仍支持搜索、订阅和任务状态命令。基础地址通常填写到 `/v1`；也接受完整 `/chat/completions` 地址。全局模型名是默认值，Telegram 与桥接可分别覆盖模型名，连接地址和密钥仍使用全局设置。

模型请求体仅包含固定意图合同和本次用户文本，不包含数据源凭据、本地目录、任务内容或搜索结果；已填写的模型密钥只放在服务认证头。连接测试会向该服务发送一次小请求。本项目的测试仅使用本地假服务，没有验证真实模型账户或收费接口。

模型只可返回 `search`、`subscribe`、`tasks`、`downloadurl` 四种 JSON 意图，未知动作、额外字段、无效或过大的响应均拒绝。生产入口的明确片名下载和订阅先由规则识别并交给选片请求，不让模型猜测写入意图。普通搜索不能被模型升级成下载或订阅；模型不能执行 shell、读取配置、选择候选或改变下载地址。模型请求上限 15 秒，响应上限 64 KiB；错误回复不包含供应商错误正文。聊天最长 4000 字，搜索或订阅词最长 200 字。

支持的命令：

| 用途 | 中文示例 | English |
| --- | --- | --- |
| 搜索 | `搜索 沙丘` 或直接输入 `沙丘` | `search Dune` |
| 订阅 | `订阅 三体` | `subscribe Silo` |
| 状态 | `任务状态` | `status` / `tasks` |
| 按片名下载 | `下载 沙丘` | `download Dune` |
| 提交直链 | `下载 https://example.com/movie.mp4` | `download https://example.com/movie.mp4` |
| 帮助 | `帮助` | `/help` |

生产入口的普通片名、搜索、按片名下载与订阅均进入持久的选片请求，依次确认作品身份、剧集季集和资源。搜索意图不会自动下载；明确下载或订阅在身份与资源充分确定时可由请求服务继续处理，不会退回原始资源的直接写入。用户明确给出的 HTTP(S) 直链保留原有手工下载路径，并提示它尚未确认作品身份；不会将直链当作片名查询。下载任务入队不代表文件已完成，进度与实际文件状态以任务页面为准。

## 仅输入片名的默认动作

管理员在向导或设置页保存 `defaultTitleAction`（`search` / `download` / `subscribe`），客户端与已授权渠道共用。缺字段的旧配置按 `search` 读取，旧客户端未提交此字段时保留已有值。默认下载/追更只作用于可判定的片名，固定采用用户原片名（可去除成对书名号）进入 Requests；不能回退到未确认身份的旧写接口。显式命令优先且不经模型改写动作或目标；模型只对默认搜索的裸输入辅助理解，不能提升写权限。已有待确认请求保留原 intent/revision，修改默认值不会升级旧请求。

否定、控制、疑问和裸链接不会套用默认写动作。特殊的真实片名可完整使用《片名》明确声明；直链仍需明确的下载指令。此设置不改变资源搜索页或已有订阅的自动下载开关。

## 渠道下载审批（可选）

设置中心 → 渠道 的「渠道下载审批」默认关闭：已授权渠道按指令直接创建任务。开启后，渠道选完资源会先停在「待批准」，网页端的请求卡片提供「批准并创建任务 / 拒绝」，批准前不产生下载任务；渠道侧不能自行批准，直链下载命令也改为提示到网页端确认，不再直接建任务。网页端管理员自己的操作不受影响。关闭开关不会改变已经停在待批准的请求，仍需明确批准或拒绝，避免半途丢失状态。

决定之后，**申请人会收到一条消息**：批准时是「已开始下载，完成后会再通知你」，拒绝时是「未创建下载任务」。消息走既有通知桥接的 `poll` 通道（与下载完成通知同一条队列），因此需要桥接已启用且 `poll` 正在运行；网页端管理员自己发起的请求不产生这类消息。同一次决定重复提交只排一条，不会刷屏。若通知队列已满，决定本身仍然成功——审批结果不会因为发不出消息而回滚，网页端仍能看到状态。

上面的开关是**全局默认**。需要区别对待时，同一张卡片里可以按渠道设置三态：跟随全局 / 需批准 / 免批准（Telegram、微信、QQ、飞书各一项）。判定顺序是**单渠道覆盖优先，其次全局开关**；网页管理员自己的操作始终不受影响。缺字段的旧配置等价于全部「跟随全局」，升级后行为不变。平台判定从宽：只要归属前缀像渠道就算渠道，宁可多要一次批准，也不让畸形标识绕过闸门；通知地址本身仍由原有规则严格校验。

每次决定都会留档：请求上记录「批准/拒绝 + 时间 + 操作人」，另在独立历史里保留一条（含申请人、片名）。请求本身 1 天后会过期清理，历史不受影响，保留最近 200 条。

助手页的「操作记录」把两类事件合成一条时间线：**任务创建**（网页手动、渠道指令、订阅自动下载）与**审批决定**。任务记录标注来源与资源类型，审批记录标注批准/拒绝与操作人，各自保留最近 500 / 200 条，界面展示最近 50 条。任务审计与任务创建在同一个事务里写入，不会出现「有任务没记录」；重复提交同一资源只会复用原任务，不重复记一条。审批完成后无需手动刷新，列表会自动更新。

## 搜索来源诊断

聊天回复会区分来源未配置、全部失败、部分成功，以及已查来源全部成功但暂时没有匹配。部分来源失败时，已有资源仍可继续选择；来源返回格式错误会显示失败，不当作没有资源。诊断随请求或订阅保存，便于之后核对。

片名检索使用PanSou、OpenList、MoviePilot和已配置的TG频道；TMDB元数据、115/阿里分享账号不能代替检索源。Compose已带PanSou，无需另起第二套；已有配置不保证连通。可先在设置中检查来源，再明确重试检索。软件不会自动重复提交结果未知的操作，命令格式沿用下文。

## 频道内继续选片

回复包含请求 ID、最多二十个作品候选的年份和电影/剧集类型，或最多五个资源及其匹配说明。可在当前频道使用以下命令：

| 操作 | 命令 |
| --- | --- |
| 选择作品身份 | `选择 requestId 2` |
| 选择本会话最新待确认请求的作品候选 | `第2个` 或 `第二个`（中文支持第一至第二十个） |
| 明确选择匹配资源 | `资源 requestId 2` |
| 为115或阿里分享补充提取码 | `资源 <requestId> <编号> 提取码 <4位字母数字>`，如 `资源 requestId 2 提取码 a1b2` |
| 追更已浏览的115或阿里目录 | `订阅目录 <requestId>` |
| 明确季集 | `季集 requestId S02E03` |
| 明确接受不确定资源 | `确认资源 requestId 2` |

115和阿里分享都需先按[分享下载说明](SHARE_RESOLVER.md#使用)启用。文本入口沿用同一资源、提取码和目录订阅命令，回复会区分「115」与「阿里云盘」。需要提取码时，在资源命令后附上4位字母数字；访问记录加密保存，不在回复或普通资源列表中回显。文件夹和分页仍按回复编号选择，导航不会启动下载；选中文件须经过匹配或必要的确认才会入队。

阿里可匿名浏览；下载与追更前请在设置中保存自己的Web RefreshToken，不要发到聊天。它不是官方OpenAPI token，Mnemo没有扫码或浏览器自动取凭据入口。验证和授权结果未知的处理见[阿里适配说明](ALIPAN_ADAPTER.md#使用)。

追更目录需先确认作品、年份和电视剧季数，并成功浏览目标目录，再单独发送`订阅目录 <requestId>`。这条命令不附文件编号或提取码，会包含下级目录；原有`订阅 剧名`仍创建按作品聚合订阅。暂停、删除和扫描上限见[目录追更说明](SHARE_RESOLVER.md#目录追更与限制)。

编号由服务器保存的候选或资源 ID 解析，不接受消息中的自造 ID 或自然语言推测 URL。每次作品、季集和资源选择都附带本次读取的 request.revision，服务端以 expectedRevision 拒绝并发产生的旧版本选择。作品命令“选择”和“第N个”只选择身份，不会在请求进入资源阶段后变成下载；资源必须明确使用“资源”命令。不确定资源必须使用“确认资源”命令；已知不匹配资源即使确认也拒绝。没有元数据候选时需在 Web 界面明确作品类型、标题和年份，不会默认猜测。显式 requestId 可以恢复本 owner 的更早待确认请求；“第N个”只作用于本 owner 最新待确认请求的作品候选。过期、已结束、跨 owner 和无效编号均不会提交选择。

Telegram owner 由可信 Bot 数字 ID 与 chatId 派生；桥接 owner 由验签后的 platform 与 peer 派生。客户端不能在消息体传入 owner。任务列表可共享，但作品请求和选择相互隔离；群聊内同一个 chat/peer 共享该会话上下文，适配器仍须落实群成员权限。持久任务通知的目标同样来自服务器上下文，不能由任意请求体指定；完整状态与持久化边界见 `NOTIFICATIONS.md`。

## Telegram：原生 Bot 长轮询

在设置中填写 Bot Token、允许的 Chat ID，启用 Telegram；空白名单默认拒绝所有消息并停止轮询。Chat ID 必须是数字字符串，群组 ID 可以为负数；最多 100 个。服务不通过未知聊天的私密消息自动学习白名单。需先在 Telegram 主动联系 Bot 或将其加入已授权群组。

同一 Token 只运行一个轮询实例；外部已设置的 webhook 或其他轮询客户端可能冲突，需由管理员自行处理。每次最多读取 20 条更新，串行处理文字消息，不接受 Bot 消息；未授权聊天不会得到回复。没有照片、语音或文件解析。选片可使用回复中的请求 ID 和选择命令，也可在 Web 界面继续。渠道只通过已配置 Bot 的 `sendMessage` 向授权聊天回复或发送其关联任务的结果。

轮询上限 25 秒、回复上限 10 秒；失败使用有上限的退避和抖动。发送回复结果未知时不会自动重发。配置更新后由服务停止旧轮询并启动新轮询；生命周期取消信号同时传入 request/select，并与调用方信号合并。停止后在途识别、搜索必须在后续副作用前检查取消，晚到的响应不能继续自动创建下载、订阅或发送回复；停止前已提交的任务不会自动撤销。

当前 offset 只在内存保存为一个数字。重启时尚未确认的更新可能再次出现；不能据此声称 Telegram 命令具备持久的 exactly-once 执行。已提交操作的结果可在 Web 界面核对。

`sources.telegramChannels` 是媒体搜索源设置；`channels.telegram` 是聊天入口。配置搜索频道不代表授权该频道的所有成员操作 Bot，也不等于实现了私人频道抓取。搜索能力以对应数据源适配器的实际支持范围为准。

### Telegram 持久结果通知

启用通知服务后，与轮询共用同一 owner 生命周期的发送循环每五秒处理最多四条，串行发送。每次认领和发送前重新检查当前 Token 的公共 Bot 数字 ID、启用状态与 Chat ID 白名单；旧 Bot 或已停用聊天的通知不会被认领。服务先持久保存 `dispatching` 与 claim token，再调用 `sendMessage`，请求上限十秒。

Telegram API 明确成功且返回 message_id 后记录 `delivered` 和该 ID；明确的 400/401/403/429 拒绝记录 `rejected`。5xx、网络错误、超时、取消或不能核实的响应记录 `unknown`。停止后不开始新的认领或发送，已认领的取消结果仍需落账。循环异常会报告脱敏提示，不输出 Token 或供应商正文。通知服务未配置时发送循环保持禁用。

`delivered` 仅证明平台接口接受，不代表用户已读。`unknown` 与 `rejected` 均不会自动重发；结果未知时由管理员核对，明确接受重复风险后才能重试。任务查询的即时文字回复保持原有行为。

## 微信、QQ、飞书：签名适配桥接

这三项提供相同的 HTTP 适配桥接，**不是已接通的原生平台登录或机器人适配器**。管理员需自行运行平台适配器，完成平台认证、回调验签、用户/群组授权、消息转换与回复投递。微信、QQ、飞书原生回调不能直接发送到这里；平台账号、应用审核及公开回调部署尚未实际验证。Mnemo 只向适配器返回 `ChatReply` JSON，不向这三个平台主动发消息。

在设置中启用桥接并填写共享签名密钥，建议使用至少 32 字节的随机值。适配器拥有这项授权后可提交操作，必须自行限制允许的用户和群组。Mnemo 要求非空 `peer` 并将它纳入签名，但不会把它当成独立的用户权限系统。

请求：`POST /api/channels/bridge/:platform`，其中 `platform` 只能是 `wechat`、`qq` 或 `feishu`。

JSON 仅含三个字符串字段：

```json
{"eventId":"unique-platform-event-123","peer":"authorized-chat-id","text":"搜索 沙丘"}
```

`eventId` 为 1–128 位字母、数字、`_ . : -`，同一平台和 peer 下必须稳定且唯一；不能在重试时更换。`peer` 最长 200 字且不含控制字符；`text` 为 1–4000 字的非空文本。签名完成后，Mnemo 才会 trim 消息文本并交给 Agent。

必需的请求头：

| 请求头 | 内容 |
| --- | --- |
| `Content-Type` | `application/json` |
| `X-Mori-Timestamp` | Unix 时间戳秒数的十进制字符串，与服务器当前时间相差最多 5 分钟 |
| `X-Mori-Signature` | HMAC-SHA256 的 64 位十六进制结果 |

签名原文为 UTF-8 编码的 `JSON.stringify([platform, timestamp, eventId, peer, text])`，其中 timestamp 保留请求头中的字符串形式，三个 JSON 字段保留原始值。使用共享签名密钥计算 HMAC；服务使用固定长度的 timing-safe 比较。签名包含平台，不能跨平台复用。适配器到 Mnemo 的远程连接应使用 HTTPS。

Node.js 适配器中的签名片段（`secret` 来自适配器自己的安全配置）：

```js
import { createHmac } from 'node:crypto';
const timestamp = String(Math.floor(Date.now() / 1000));
const signature = createHmac('sha256', secret)
  .update(JSON.stringify([platform, timestamp, body.eventId, body.peer, body.text]), 'utf8')
  .digest('hex');
```

成功返回 `ChatReply`，包括 `text` 和可选的 `request`、`results`、`task`、`subscription`；`request` 包含当前选片阶段与可用候选。签名字段和算法保持不变。缺字段返回 400，未启用或未知平台 404，签名无效或过期 401，已接收事件 409，容量满 429。最多同时处理四个请求；满载时尚未执行的事件可保留原 eventId 稍后重试。已接收事件在签名失效前保留，最多 2000 项；容量满时拒绝新事件，不淘汰仍有效事件。收到超时或 409 后应先核对操作结果，避免通过新 eventId 重复订阅或下载。

每个已验签的在途请求有一个取消控制器，最多四个。客户端中断请求或响应连接提前关闭会向下取消 request/select；主服务在配置更新成功及关闭时调用 registerChannelRoutes 返回的 cancelInFlight，同步撤销旧在途请求。取消请求仍占用原并发名额，直到处理结束；不会因取消放大并发，也没有后台配置轮询。取消不代表撤销已经提交的下载，结果未知仍需在 Web 核对。

### 签名通知 poll / ack

现有消息路由与签名不变。通知使用两个独立签名域，沿用 `X-Mori-Timestamp`、`X-Mori-Signature` 与 ±5 分钟窗口：

| 路由 | JSON 字段 | HMAC-SHA256 原文（UTF-8 JSON.stringify） |
| --- | --- | --- |
| `POST /api/channels/bridge/:platform/notifications/poll` | `{peer,nonce}` | `['notifications.poll',platform,timestamp,peer,nonce]` |
| `POST /api/channels/bridge/:platform/notifications/ack` | `{peer,id,claimToken,outcome,receipt?}` | `['notifications.ack',platform,timestamp,peer,id,claimToken,outcome,receipt||'']` |

JSON 仅允许表内字段，platform 仍只支持 wechat、qq、feishu。peer 与消息路由相同，签名使用原始值。nonce 为 1–128 位字母、数字或 `_ . : -`；同一目标的重复 nonce 在签名有效期内返回 409，缓存最多 2000 项，满载返回 429。新的 poll 必须使用新 nonce；nonce 不是持久通知身份。

poll 仅认领签名平台与 peer 的待发送记录，每次最多十条，返回 `{notifications:NotificationClaim[],serverTime:ISO}`。每条 claim 含 id、taskId、text、claimToken、expiresAt；读取与认领均不代表已投递，不提供全局通知列表。已 dispatching 或结果未知的记录不会因重复 poll 再次认领。

ACK 的 id 为 1–128 位字母、数字或 `_ . : -`；claimToken 为非空、最长 256 字且不含空白或控制字符的字符串。outcome 仅允许 delivered、unknown、rejected；receipt 是可选的最长 512 字、无控制字符的回执标识，不能使用供应商错误正文。目标与当前 claim token 必须匹配；旧尝试、跨 peer 的回执返回 409。同一已投递 claim 的相同 ACK 可幂等重放。消息签名、poll 签名和 ACK 签名不能跨路由复用。

通知服务未配置或桥接禁用返回 `503 {disabled:true,error}`；无效字段 400，签名无效或过期 401。通知路由与消息路由共用最多四个在途请求及 cancelInFlight。poll 认领后若响应中断或被取消，未确认交接的 claim 记录 unknown；不能据此自动发送或重新认领。平台适配器需按 `NOTIFICATIONS.md` 在真正发送前持久保存自己的投递日志，成功后 ACK，结果未知时不盲目重发。

重放记录保存在进程内存，重启后清空；重启后五分钟内的旧签名仍可能再次通过。需要跨重启的严格重放保护时，应在平台适配器持久化平台事件 ID 并去重。桥接路由不依赖浏览器管理员会话，始终要求有效 HMAC；浏览器设置及其他 API 仍由管理员会话保护。
